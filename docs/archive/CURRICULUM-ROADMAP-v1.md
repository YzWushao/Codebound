合计 100 关，其中新增关卡方案为 80 关。每个正式幕包含四个区域，每区域 10 关；关数是教学设计结果，不作为引擎固定限制。第三幕后根据试玩反馈安排文件、异常处理、模块与小项目，暂不预设一个无限膨胀的课表。

Python 是本体主线。C、C++ 等仍按语言 DLC 独立规划；本方案不把 Python 章节当成 DLC。

## 2. 每个区域的教学节奏

| 区域内位置 | 作用 | 支持方式 |
| --- | --- | --- |
| 1～2 | 用熟悉的问题引入一个新概念 | 动作演示、带注释示例、较完整的起始代码 |
| 3～4 | 练习同一概念的变化与边界 | 给代码骨架，让玩家填写核心语句 |
| 5～6 | 迁移到新输入或新路线 | 减少骨架，保留例子和三级提示 |
| 7～8 | 组合两个已学概念 | 明确任务拆解，展示变量变化 |
| 9 | 修错、边界或独立练习 | 给一段能定位问题的代码或测试数据 |
| 10 | 区域综合关 | 提供步骤清单，逐项反馈，允许分步完成 |

不把每关都设计成「补最后一行」。交替使用行动关、终端练习和修错关。行动关练习机器人路线，终端题训练普通 Python，修错题帮助玩家读懂程序。

每关都须有：剧情目标、单一主要知识点、知识解释、注释示例、起始代码、三级提示、参考解法及测试。综合关只组合已经教过的知识。

三级提示依次为「思路」「所需语法」「接近解法的局部骨架」。最后一级可帮助玩家完成任务，但应解释原因；查看提示不影响通关资格。计时与排名可以以后增加，基础课程优先让玩家愿意尝试和重试。

## 6. 一关展开后的样例：第 48 关「留下合格电池」

剧情：仓库收到一批电池，只有电量达到门槛的电池可以装车。玩家需要按原来的顺序留下它们。

主要知识：遍历列表，在条件成立时把当前元素追加到新列表。前置知识为 for、if、比较、空列表与 append。

输入约定：第一行是合格门槛；第二行是空格分隔的电量，电量行允许为空。输出合格电量的 Python 列表。

先给一个不同任务的注释示例：

```python
# 从编号里留下偶数，观察新列表如何逐渐增加。
numbers = [3, 4, 7, 8]
chosen = []
for number in numbers:
    if number % 2 == 0:
        chosen.append(number)
print(chosen)
```

起始代码直接提供输入整理代码，让本关集中练习筛选：

```python
minimum = int(input())
batteries = []
for text in input().split():
    batteries.append(int(text))

qualified = []
# 遍历 batteries；合格时追加到 qualified。

print(qualified)
```

三级提示：

1. 准备一个空的新列表，逐个检查原列表中的电量。
2. 使用 `for energy in batteries`，在循环内判断 `energy >= minimum`。
3. 条件成立的缩进行中写 `qualified.append(energy)`；循环结束后输出新列表。

| 用途 | 输入两行 | 预期输出 |
| --- | --- | --- |
| 普通情况 | `50`；`35 50 80` | `[50, 80]` |
| 都合格 | `20`；`20 30` | `[20, 30]` |
| 都不合格 | `90`；`10 40` | `[]` |
| 空电量行 | `50`；空行 | `[]` |
| 保留重复和顺序 | `50`；`60 20 60 55` | `[60, 60, 55]` |

反馈应同时展示原列表、当前检查的元素、条件结果和新列表。若只通过当前样例但变式失败，提示查看门槛边界或保留顺序，不只显示「答案错误」。

## 8. 判定与内容验收

每关至少准备一组可见样例和两组变式；涉及边界时追加对应案例。题面写清输入格式、输出格式、合法范围和空结果约定。

- 数值题：零、相等、整除与余数、负数是否允许。
- 字符串题：单字符、中文、首尾空白、空串是否允许。
- 列表题：单元素、空列表、重复、没有合格项、保持顺序。
- 查找题：目标在首尾、重复目标、不存在、约定索引起点。
- 字典题：缺失键、重复记录、默认值和输出顺序。
- 函数题：多个参数组合、返回值被实际使用、空输入容器。

教学要求检查使用了对应知识点，也检查它是否参与了任务处理；单纯出现一个没有调用的空函数不算完成函数训练。允许不同的正确解法，不按代码逐字匹配。

练习数据先控制在便于逐步观察的范围：列表通常不超过 20 项，排序演示不超过 8 项，表格通常不超过 4×4。沿用并核对现有 3000 行追踪、150 动作和 650 事件上限；综合任务超过预算时拆成子任务，不先提高上限掩盖设计问题。
