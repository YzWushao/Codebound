# 安装与升级入口

更新：2026-11-01。Alpha.4 使用同一个 Setup.exe 完成首次安装、升级与同版本修复。

## 行为

- 沿用稳定的 appId 与 NSIS 安装标识，从当前用户和系统级安装记录查找安装位置。
- 同时存在两种安装时，默认选择当前用户的安装；显式作用域参数仍受支持。
- 安装位置内同时存在游戏与卸载程序才进入自动升级；仅解压的便携版不算已安装。
- 自动升级跳过作用域和目录选择页，直接进入安装进度，保留原目录；完成页仍显示结果。
- 首次安装、过期注册信息或缺失程序文件显示正常安装向导。
- 系统级安装仍遵循 Windows 的管理员权限与 UAC 要求。
- 先发送正常关闭消息，让游戏保存；无法正常退出时提示用户关闭或取消，不强制终止。
- 复用 electron-builder 的旧版卸载、数据保留、注册表与快捷方式更新逻辑。

## 实现与维护

build/installer.nsh 通过 NSIS 自定义钩子扩展现有 assisted installer。为复用其页面与数据保留机制，扩展了 electron-builder 26.18 的 isUpdated 条件。升级依赖时应重新构建并运行安装器集成测试。

测试入口：scripts/test-installer.ps1，首次可使用 -Build。测试使用独立应用标识、安装目录、注册表项与进度样本；测试产物及报告位于被 Git 忽略的 .local/ 中。生产构建不启用 QA 标记，也不包含测试窗口程序。

## 本轮验证

- 159 项自动检查通过，140 关内容未改变。
- 生产安装包构建通过，打包资源的桌面冒烟通过。
- 首次运行显示正常目录向导。
- 从基线 Alpha.3 安装升级到 Alpha.4，普通启动方式无须再次选择安装范围或目录。
- 使用额外目录参数时，实际升级文件仍写入原安装目录，安装后的 app.asar 与新构建一致。
- 正常关闭测试窗口后才替换程序，保存标记成功写入。
- 进度样本在升级和同版本修复前后哈希一致。
- 程序文件缺失时，仍存在的旧注册项不会误触发升级，改为显示安装向导。
- 测试安装已卸载，独立注册项已清理；真实玩家存档哈希保持不变。

当前用户作用域已进行真实安装与升级测试。系统级安装/UAC、两种作用域共存及跨用户账户路径已审阅并编译，尚未进行完整管理员账户回归。应用内自动下载更新不属于此入口；当前用法为下载新版 Setup.exe 后运行。
